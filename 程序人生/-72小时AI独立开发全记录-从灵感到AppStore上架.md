## 🎯 1. Day 0：选品——从 100 个想法筛到 1 个

### 不要一上来就写代码

独立开发最常见的翻车原因不是技术不行，是选了一个没人要的产品。我的第一步不是打开 IDE，而是打开 Claude Code：

```bash
> 我想做一个独立开发的移动 App，目标用户是每天通勤的上班族。
  请给我 20 个产品创意，每个包含：
  1. 一句话描述
  2. 目标用户痛点
  3. 现有竞品分析
  4. 技术实现复杂度（1-5 分）
  5. 变现路径
```

AI 输出了 20 个想法。我又追加了一轮：

```bash
> 对这 20 个想法用以下维度打分（1-10 分），按总分排序：
  - 市场规模
  - 竞品密度（越少越好）
  - 技术实现难度（越低越好）
  - 用户付费意愿
  - 72 小时内能否做出 MVP
```

### 最终选定的方向

经过两轮筛选和我自己的判断，最终选定了一个**通勤白噪音 + 专注计时器**的工具 App。理由：

| 评估维度 | 分数 | 分析 |
|---------|------|------|
| 市场规模 | 8/10 | 全球通勤人口数亿，白噪音市场年增 15% |
| 竞品密度 | 6/10 | 有 Noisli、Calm 等巨头，但「通勤场景专属」的细分赛道几乎空白 |
| 技术难度 | 3/10 | 音频播放 + 计时器 + 本地存储，Flutter 完全覆盖 |
| 付费意愿 | 7/10 | 免费基础音效 + 付费高级音景 + 订阅模式 |
| 72h 可行性 | 9/10 | 核心功能简单，不需要后端 |
| **总分** | **33/50** | ✅ 通过筛选 |

> **选品的核心原则：不是选你最想做的，是选「市场有缺口 × 技术够简单 × 72 小时能交付」的交集。**

## 📐 2. Day 0.5：用 OpenSpec 定义产品规格

选品之后，大部分人会直接开始写代码。别急——**先写规格**。

为什么？因为接下来 AI 要帮你写大量代码，如果你连产品长什么样都没想清楚就让 AI 开搞，AI 会按自己的理解瞎发挥。规格就是给 AI 划边界。

### 逆向竞品生成规格

我用 OpenSpec 分析了 3 个竞品：

```bash
> 请分析以下 3 个白噪音 App 的核心功能，提炼出一份产品规格：
  1. Noisli（Web/移动端白噪音工具）
  2. mynoise.net（参数化音景生成器）
  3. Focus@Will（专注音乐订阅服务）
  
  输出格式：功能清单 + 用户流程 + 技术架构
```

### 功能优先级矩阵

基于 AI 输出，我手动筛选并分级：

| 优先级 | 功能 | 说明 | 72h 能做到？ |
|--------|------|------|------------|
| **P0** | 白噪音播放器 | 8 种基础音效，支持混音 | ✅ |
| **P0** | 专注计时器 | 番茄钟模式 + 自定义时长 | ✅ |
| **P0** | 音量独立控制 | 每种音效独立调节音量 | ✅ |
| **P1** | 音景预设 | 预定义的音效组合（咖啡馆/雨天/办公室） | ✅ |
| **P1** | 统计面板 | 本周专注时间、连续天数 | ✅ |
| **P2** | 自定义音景保存 | 用户自己调配并保存 | ⚠️ 视时间 |
| **P2** | 付费解锁高级音效 | IAP 内购 | ❌ 先跳过 |
| **P3** | 社交分享 | 分享专注成就到社交媒体 | ❌ 先跳过 |

72 小时的目标很清楚：**P0 + P1 全部做完，P2 视时间，P3 不碰**。

### AI 生成的 PRD vs 手搓 PRD

| 维度 | AI 生成（5 分钟） | 手写（2 小时） |
|------|------------------|---------------|
| 功能覆盖 | ⭐⭐⭐⭐ 全面但有冗余 | ⭐⭐⭐⭐⭐ 精准 |
| 用户流程 | ⭐⭐⭐ 偏理想化 | ⭐⭐⭐⭐ 贴近真实使用 |
| 技术可行性判断 | ⭐⭐ 不了解项目约束 | ⭐⭐⭐⭐⭐ 心中有数 |
| 综合效率 | ⭐⭐⭐⭐⭐ 快到离谱 | ⭐⭐ 慢但踏实 |
| **最佳实践** | **AI 出初稿 → 人工精修** | 时间充裕时的保底方案 |

> **让 AI 写 80% 的 PRD，自己修 20%——这是投入产出比最高的姿势。**

### AI 生成代码的 5 个常见翻车点

在这一天的开发中，AI 生成的代码翻了 5 次车，每次都有规律：

| # | 翻车现象 | 根因 | 修复方式 |
|---|---------|------|---------|
| 1 | 音频播放报 `AssetNotFound` | AI 用了错误的 asset 路径格式 | 手动改成 `assets/audio/xxx.mp3` |
| 2 | 多音频同时播放时卡顿 | AI 每次播放都 `new AudioPlayer()`，没有资源池 | 让 Claude Code 重新设计对象池 |
| 3 | 计时器后台被系统杀掉 | AI 用了 `Timer.periodic`，不适合后台 | 用 `flutter_background_service` 替换 |
| 4 | Riverpod Provider 循环依赖 | AI 设计的 Provider 互相 watch | 提取公共 state 到独立 Provider |
| 5 | iOS 通知权限没请求 | AI 忘了加 iOS 端的权限配置 | 手动加 `Info.plist` + 权限请求代码 |

> **AI 写代码像一个经验丰富但粗心的实习生——逻辑对了八九成，但环境配置和边界情况总会漏。**

```dart
// 音效卡片的按压动画
class SoundCard extends StatefulWidget {
  // ...
}

class _SoundCardState extends State<SoundCard> 
    with SingleTickerProviderStateMixin {
  late AnimationController _controller;
  
  @override
  Widget build(BuildContext context) {
    return GestureDetector(
      onTapDown: (_) => _controller.forward(),
      onTapUp: (_) => _controller.reverse(),
      child: AnimatedBuilder(
        animation: _controller,
        builder: (context, child) {
          return Transform.scale(
            scale: 1.0 - (_controller.value * 0.05),
            child: Container(
              decoration: BoxDecoration(
                gradient: LinearGradient(
                  colors: widget.isActive 
                    ? [Color(0xFF6C5CE7), Color(0xFF00CEC9)]
                    : [Color(0xFF161B22), Color(0xFF21262D)],
                ),
                borderRadius: BorderRadius.circular(20),
                boxShadow: widget.isActive ? [
                  BoxShadow(
                    color: Color(0xFF6C5CE7).withOpacity(0.3),
                    blurRadius: 20,
                    spreadRadius: 2,
                  ),
                ] : null,
              ),
              child: child,
            ),
          );
        },
      ),
    );
  }
}
```

## 🧪 5. Day 2.5：测试与性能调优

UI 搞定了，但别急着提审——先跑一轮测试和性能检查。

```bash

```

Claude Code 生成了 28 个测试用例，其中 24 个直接通过，4 个需要手动调整 mock 数据。

### 性能分析

用 Flutter DevTools 检查了关键指标：

| 指标 | 优化前 | 优化后 | 业界基准 |
|------|--------|--------|---------|
| 冷启动时间 | 2.8s | 1.2s | < 2s ✅ |
| 播放器页帧率 | 52 fps | 60 fps | ≥ 60 fps ✅ |
| 内存占用（8 音效） | 180 MB | 95 MB | < 150 MB ✅ |
| 电池消耗（30min） | 8% | 4% | < 5% ✅ |

### 优化手段

| 问题 | 原因 | 修复 |
|------|------|------|
| 冷启动慢 | 一次性加载 8 个音频文件 | 改为懒加载，点击时才加载 |
| 帧率掉 | 粒子动画用了 CustomPainter 重绘 | 改用 RepaintBoundary 隔离 |
| 内存高 | 音频 buffer 全量加载到内存 | 改用 streaming 模式 |
| 电量高 | 音量 0 的 Player 也在消耗 CPU | 音量归零时 pause 而不是 mute |

### 什么环节 AI 最有用 vs 最没用

| 环节 | AI 有用程度 | 说明 |
|------|-----------|------|
| 选品 Brainstorming | ⭐⭐⭐⭐ | 发散思路很好，但最终还得人拍板 |
| 写 PRD | ⭐⭐⭐⭐⭐ | 出初稿极快，改比写容易 |
| 搭项目骨架 | ⭐⭐⭐⭐⭐ | 最省时间的环节 |
| 写业务逻辑 | ⭐⭐⭐⭐ | 主线逻辑准确，边界情况需要补 |
| 做 UI | ⭐⭐⭐ | 搭骨架快，但细节打磨还得人上 |
| 做动画 | ⭐⭐ | 简单动画OK，复杂交互得自己写 |

## ✅ 8. 独立开发者 × AI 最佳实践 Checklist

### 选品阶段
- [x] 用 AI 发散 20+ 个想法，不要自己闷着想
- [x] 用数据维度打分筛选，不要凭感觉
- [x] 验证"72 小时可行性"——技术复杂度 ≤ 3 分才动手
- [x] 确认变现路径——不赚钱的事不在 72 小时内做

### 开发阶段
- [x] 先写规格再写代码——给 AI 划清边界
- [x] Cursor 做 UI，Claude Code 做逻辑——双兵不混用
- [x] AI 生成的代码 100% 要过一遍——尤其是路径、权限、边界情况
- [x] 每完成一个模块就跑一次——不要攒到最后一起测

### 上架阶段
- [x] 截图用真机录屏 → 截图——不要用模拟器
- [x] 隐私政策让 AI 写初版，自己检查法律合规
- [x] 第一次提审预留被拒的心理准备
- [x] TestFlight 至少测 3 台不同设备

### ❌ 不要做的事

| 反模式 | 后果 |
|--------|------|
| 不写规格直接让 AI 写代码 | AI 会按自己理解做，返工成倍增加 |
| 一个 prompt 就想搞定整个 App | 上下文爆炸，质量直线下降 |
| AI 生成的代码不看直接用 | 线上炸了都不知道为什么 |
| 在 72 小时内追求完美 | 你不是在做艺术品，先上线再迭代 |
| 选了一个技术复杂度 5 分的项目 | 三天做不完，士气崩溃 |
