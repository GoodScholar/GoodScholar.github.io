## 📊 关键词搜索 vs 语义搜索

| 维度 | 关键词搜索 | 语义搜索 |
|------|----------|---------|
| 搜索「好吃的面馆」 | 必须包含「面馆」二字 | 能找到「拉面」「面条」「手擀面」 |
| 搜索「心情不好」 | 匹配「心情」「不好」 | 能找到「焦虑」「低落」「抑郁」 |
| 实现方式 | SQL LIKE / 全文索引 | Embedding → 向量相似度 |
| 准确性 | 字面匹配，易遗漏 | 语义理解，召回更全 |
| 成本 | 接近免费 | 需要 Embedding API + 向量库 |

> **语义搜索不替代关键词搜索，而是互补。最佳实践是两者混合：先语义召回 → 再关键词过滤。**

## 🧠 1. 什么是 Embedding？

### 核心概念

Embedding（嵌入向量）是把文本转化为一组浮点数数组（向量），让「语义相近」的文本在数学空间中「距离更近」。

```
"我想吃拉面" → [0.12, -0.34, 0.56, 0.78, ...] (1536 维)
"好吃的面条" → [0.11, -0.31, 0.58, 0.76, ...] (1536 维)
"今天天气好" → [0.89, 0.22, -0.14, 0.03, ...] (1536 维)

距离("我想吃拉面", "好吃的面条") = 0.05  ← 很近！语义相似
距离("我想吃拉面", "今天天气好") = 0.92  ← 很远！语义不同
```

### Embedding 模型对比

| 模型 | 供应商 | 维度 | 价格/1M Token | 适合 |
|------|--------|------|-------------|------|
| **text-embedding-3-small** | OpenAI | 1536 | $0.02 | 性价比最高，大部分场景首选 |
| **text-embedding-3-large** | OpenAI | 3072 | $0.13 | 精度要求极高 |
| **Cohere embed-v3** | Cohere | 1024 | $0.10 | 多语言支持好 |
| **BGE-M3** | BAAI | 1024 | 免费（本地） | 中文场景 + 隐私要求 |

### 生成 Embedding

```typescript
// Node.js - 使用 OpenAI SDK
import OpenAI from 'openai'

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY })

async function getEmbedding(text: string): Promise<number[]> {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: text,
  })
  return response.data[0].embedding // 1536 维向量
}

// 批量生成（更高效）
async function getEmbeddings(texts: string[]): Promise<number[][]> {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: texts, // 支持数组输入
  })
  return response.data.map((d) => d.embedding)
}
```

## 🗄️ 2. 向量数据库选型

### 主流方案对比

| 数据库 | 类型 | 适合规模 | 部署方式 | 成本 | 推荐度 |
|--------|------|---------|---------|------|--------|
| **pgvector** | PostgreSQL 扩展 | 1-100 万条 | 自托管 / Supabase | 低 | ⭐⭐⭐⭐⭐ |
| **Pinecone** | 全托管 SaaS | 1-1000 万条 | 云服务 | 中 | ⭐⭐⭐⭐ |
| **Milvus** | 分布式引擎 | 1 亿+ | 自托管 / Zilliz Cloud | 高 | ⭐⭐⭐⭐ |
| **Chroma** | 轻量嵌入式 | 1-10 万条 | 进程内 / Docker | 免费 | ⭐⭐⭐ |
| **Qdrant** | Rust 原生 | 1-1000 万条 | Docker / Cloud | 中 | ⭐⭐⭐⭐ |

### 选型建议

```
你的数据量多大？
    │
    ├── < 10 万条 → Chroma（本地开发）/ pgvector（生产）
    │
    ├── 10-100 万条 → pgvector（已有 PG）/ Pinecone（省运维）
    │
    └── > 100 万条 → Milvus / Qdrant
```

> **对于大部分 App，pgvector 就够了。不要为了「向量数据库」去引入新的基础设施——大概率你已经在用 PostgreSQL 了。**

## 🔧 3. 实战：pgvector 语义搜索

### 数据库设置

```sql
-- 1. 安装 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. 创建文章表
CREATE TABLE articles (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  category TEXT,
  embedding vector(1536), -- 1536 维向量
  created_at TIMESTAMP DEFAULT NOW()
);

-- 3. 创建向量索引（加速相似度搜索）
CREATE INDEX ON articles
  USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);
-- lists 参数：约等于 sqrt(总行数)，10 万行用 316
```

### 数据入库（indexing）

```typescript
// scripts/index-articles.ts
import { Pool } from 'pg'
import OpenAI from 'openai'

const pool = new Pool({ connectionString: process.env.DATABASE_URL })
const openai = new OpenAI()

async function indexArticles(articles: Article[]) {
  // 批量生成 Embedding
  const texts = articles.map((a) => `${a.title}\n${a.content.slice(0, 2000)}`)
  const embeddings = await getEmbeddings(texts) // 上面定义的函数

  // 批量插入
  for (let i = 0; i < articles.length; i++) {
    await pool.query(
      `INSERT INTO articles (title, content, category, embedding)
       VALUES ($1, $2, $3, $4)`,
      [
        articles[i].title,
        articles[i].content,
        articles[i].category,
        `[${embeddings[i].join(',')}]`, // pgvector 格式
      ]
    )
  }

  console.log(`已索引 ${articles.length} 篇文章`)
}
```

### 搜索接口

```typescript
// app/api/search/route.ts
import { Pool } from 'pg'
import OpenAI from 'openai'

const pool = new Pool({ connectionString: process.env.DATABASE_URL })
const openai = new OpenAI()

export async function POST(req: Request) {
  const { query, limit = 10, category } = await req.json()

  // 1. 把用户查询转为 Embedding
  const queryEmbedding = await getEmbedding(query)

  // 2. 向量相似度搜索
  let sql = `
    SELECT id, title, content, category,
           1 - (embedding <=> $1::vector) AS similarity
    FROM articles
  `
  const params: any[] = [`[${queryEmbedding.join(',')}]`]

  // 可选：分类过滤（语义 + 关键词混合）
  if (category) {
    sql += ` WHERE category = $2`
    params.push(category)
  }

  sql += ` ORDER BY embedding <=> $1::vector LIMIT $${params.length + 1}`
  params.push(limit)

  const result = await pool.query(sql, params)

  return Response.json({
    results: result.rows.map((row) => ({
      id: row.id,
      title: row.title,
      content: row.content.slice(0, 200) + '...',
      similarity: Math.round(row.similarity * 100) / 100,
    })),
  })
}
```

## 🎨 4. 前端搜索组件

### React 实现

```tsx
// components/SemanticSearch.tsx
'use client'
import { useState, useCallback } from 'react'
import { debounce } from 'lodash-es'

interface SearchResult {
  id: number
  title: string
  content: string
  similarity: number
}

export function SemanticSearch() {
  const [query, setQuery] = useState('')
  const [results, setResults] = useState<SearchResult[]>([])
  const [loading, setLoading] = useState(false)

  const search = useCallback(
    debounce(async (q: string) => {
      if (q.length < 2) return
      setLoading(true)
      try {
        const res = await fetch('/api/search', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ query: q, limit: 10 }),
        })
        const data = await res.json()
        setResults(data.results)
      } finally {
        setLoading(false)
      }
    }, 300),
    []
  )

  return (
    <div className="search-container">
      <input
        value={query}
        onChange={(e) => {
          setQuery(e.target.value)
          search(e.target.value)
        }}
        placeholder="输入你想搜索的内容（支持语义理解）"
      />

      {loading && <div className="loading">搜索中...</div>}

      <div className="results">
        {results.map((r) => (
          <div key={r.id} className="result-card">
            <h3>{r.title}</h3>
            <p>{r.content}</p>
            <span className="similarity">
              相似度: {(r.similarity * 100).toFixed(0)}%
            </span>
          </div>
        ))}
      </div>
    </div>
  )
}
```

## 💰 5. 成本分析

### Embedding 成本估算

| 数据量 | 索引成本（一次性） | 每次搜索成本 | 月搜索 10 万次 |
|--------|-----------------|------------|-------------|
| 1 万篇文章 | ~$0.10 | ~$0.000004 | $0.40 |
| 10 万篇文章 | ~$1.00 | ~$0.000004 | $0.40 |
| 100 万篇文章 | ~$10.00 | ~$0.000004 | $0.40 |

> **Embedding 搜索成本极低。索引一次后，每次搜索只需要把 query 转成向量（几个 Token），几乎免费。**

### 与传统搜索的成本对比

| 方案 | 基础设施成本 | API 成本 | 精度 |
|------|-----------|---------|------|
| SQL LIKE | ~$0 | 无 | ⭐⭐ |
| Elasticsearch | $50-200/月 | 无 | ⭐⭐⭐⭐ |
| pgvector + Embedding | $0（PG 已有） | ~$1/月 | ⭐⭐⭐⭐⭐ |
| Algolia | $29-249/月 | 按搜索量 | ⭐⭐⭐⭐ |

## ⚡ 6. 性能优化

### 索引策略

| 索引类型 | 精度 | 速度 | 适合数据量 |
|---------|------|------|----------|
| 无索引（暴力搜索） | 100% | 慢 | < 1 万 |
| IVFFlat | ~95% | 快 | 1-100 万 |
| HNSW | ~99% | 最快 | 任意规模 |

```sql
-- HNSW 索引（推荐，精度和速度最佳平衡）
CREATE INDEX ON articles
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
```

### 缓存策略

```typescript
// 对热门查询做缓存（语义级别）
import { Redis } from 'ioredis'

const redis = new Redis(process.env.REDIS_URL)
const CACHE_TTL = 3600 // 1 小时

async function cachedSearch(query: string) {
  const cacheKey = `search:${query}`

  // 1. 检查缓存
  const cached = await redis.get(cacheKey)
  if (cached) return JSON.parse(cached)

  // 2. 执行搜索
  const results = await semanticSearch(query)

  // 3. 写入缓存
  await redis.setex(cacheKey, CACHE_TTL, JSON.stringify(results))

  return results
}
```
