Mission Checkpoint: 核心引擎逻辑

Lesson 3: DAG 执行引擎初步

现在我们有了一个干净的逻辑状态 (Logical State)，接下来要解决的是核心业务问题：当用户点击“执行”时，这些节点应该以什么顺序运行？

有向无环图 (DAG) 与拓扑排序

节点编排工具（如 ComfyUI 或 tapNow）在底层都是一个 DAG（Directed Acyclic Graph）。执行引擎的第一步是将图形转换为可执行的序列，这通常通过 拓扑排序 (Topological Sorting) 来完成。

拓扑排序的基本规则：

任何一个节点的执行，都必须等待它所有的前置节点 (Incomers) 执行完毕。如果图中有环路（比如 A 指向 B，B 又指向 A），执行引擎就会陷入死循环（这也就是为什么必须是“无环”图）。

实现简易执行引擎的伪代码逻辑

在 React Flow 的生态中，我们可以利用 getIncomers 和 getOutgoers 函数来解析节点的上下游关系。一个基础的执行循环如下：

// 1. 找到所有的根节点（没有连入边 incoming edges 的节点）
const rootNodes = nodes.filter(n => getIncomers(n, nodes, edges).length === 0);

// 2. 将它们推入执行队列 (Execution Queue)
let queue = [...rootNodes];
let completedNodes = new Set();

// 3. 经典的执行循环 (Event Loop 模型)
while (queue.length > 0) {
  const currentNode = queue.shift(); // 取出队列第一个节点
  
  // 检查是否所有前置节点都已完成
  const incomers = getIncomers(currentNode, nodes, edges);
  const allIncomersDone = incomers.every(n => completedNodes.has(n.id));
  
  if (!allIncomersDone) {
    // 条件未满足，先跳过，可能后续会被重新推入（或在真实引擎中使用 Promise.all 处理并行）
    continue;
  }
  
  // 👉 执行节点业务逻辑
  await executeNodeTask(currentNode); 
  completedNodes.add(currentNode.id);
  
  // 4. 将它的下游节点推入队列
  const outgoers = getOutgoers(currentNode, nodes, edges);
  queue.push(...outgoers);
}

并行的力量与局限

上述代码是一个简单的深度优先/广度优先队列。在实际业务中，多个分支可能会并行 (Concurrent) 执行。为了应对复杂性，现代架构往往会将 executeNodeTask 包装为一个 Promise，利用事件派发 (Event Emitter) 或是状态机 (State Machine) 来管理节点状态从 pending -> running -> success/failed 的转变。

思考：如果在这个 while 循环中，某个 executeNodeTask 是一个需要用户等待 3 天才能完成的审批节点，会发生什么？ 这个 while 循环将彻底卡死前端浏览器，甚至无法持久化到后端。这就是我们下一课“工作流断点”要解决的终极问题。
