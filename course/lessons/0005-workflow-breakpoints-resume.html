Mission Checkpoint: 架构闭环

Lesson 5: 状态恢复与上下文注入 (Resume)

想象一下，昨天挂起了一个“等待审核”的工作流。今天，用户终于登录系统并点击了“同意”。我们如何重新激活引擎，让流程继续往下走？这就涉及到了断点的最后一块拼图：恢复 (Resume) 与上下文注入。

重新装载现场

引擎的重新启动，不是从根节点开始的。我们首先要从数据库加载上一节课保存的“快照”：

  • queue：由于我们在上一课挂起时，引发挂起的节点还没有被 shift 出队列，因此它还在队列的最前方。
  • completedNodes：包含了所有已经成功执行的节点数据，下游节点可以从中读取依赖数据。

上下文注入 (Context Injection)

当用户点击“同意”时，产生了一个外部输入（也就是审核结果）。我们必须将这个外部输入“注入”给那个一直处于挂起状态的节点，然后人为地将其状态修改为 SUCCESS，接着重启 while 循环！

// 外部系统或UI界面调用的 Resume 函数
async function resumeWorkflow(snapshotData, nodeId, userInput) {
  // 1. 从快照恢复现场
  let { queue, completedNodes } = snapshotData;
  
  // 2. 找到那个被挂起的节点，它应该在 queue 的头部
  const suspendedNode = queue.find(n => n.id === nodeId);
  
  // 3. 上下文注入：将用户的操作结果作为节点的最终输出
  suspendedNode.outputData = { action: userInput, timestamp: Date.now() };
  
  // 4. 将该节点标记为完成，并移除出队列
  completedNodes.add(suspendedNode.id);
  queue = queue.filter(n => n.id !== nodeId);
  
  // 5. 核心：将其所有的下游节点 (Outgoers) 推入执行队列！
  const outgoers = getOutgoers(suspendedNode, nodes, edges);
  queue.push(...outgoers);
  
  // 6. 重启执行引擎！
  startExecutionLoop(queue, completedNodes);
}
架构之美：

注意到没有？我们在 resumeWorkflow 中做的工作，其实就等价于普通节点在 executeNodeTask 成功后做的工作（赋值输出数据、移出队列、推进下游节点）。
“挂起与恢复”本质上是将引擎内部瞬间完成的操作，拉长到了人类的时间尺度，由外部事件来补全状态。
