Mission Checkpoint: 代码级调试

Lesson 2: 编排系统的调试策略 (Debugging Breakpoints)

在设计类似 ComfyUI 的系统时，你的节点和连线动辄上百个。当某个数据流没有按预期传递时，如何进行高效的代码级调试 (Debugging)？传统的 console.log 会在 React Flow 极高频的重绘中瞬间淹没你。

1. 避免 console.log 地狱：使用条件断点 (Conditional Breakpoints)

由于 React Flow 的 onNodesChange 会在每次拖拽的像素移动时触发上百次，直接在组件渲染流中打断点会导致浏览器卡死。

技巧：使用 IDE 或浏览器的条件断点
在 Source 面板中右键代码行号，选择 "Add conditional breakpoint..."，输入判断条件。例如：
node.id === 'target-execution-node' && !node.data.isReady

2. 数据流断点：在自定义节点中防御性调试

在你的自定义节点 (Custom Node) 中，业务数据是从 Zustand 还是从 props 传递进来的？如果数据出现了问题，最好的地方是在执行核心逻辑前强行挂起：

import { Handle, Position } from 'reactflow';

export default function ExecutionNode({ data, id }) {
  // 仅在发现特定异常数据时触发断点
  if (data.inputValue === undefined && process.env.NODE_ENV === 'development') {
    debugger; // 浏览器将在此完美暂停，允许你查看调用栈 (Call Stack)
  }

  return (
    <div>
      <Handle type="target" position={Position.Left} />
      <div>处理节点: {id}</div>
      <Handle type="source" position={Position.Right} />
    </div>
  );
}

3. 监听内部状态：useStoreApi (脱离渲染循环的查看)

Zustand 和 React Flow 都推荐不要在频繁更新的回调（如 onNodesChange）中读取依赖。使用 useStoreApi (Zustand) 或 useReactFlow().getState() 可以在断点挂起时，直接在控制台中调用获取当前全量状态，而不会触发 React 渲染。
