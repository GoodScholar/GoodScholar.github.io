Mission Checkpoint: 架构核心机制

Lesson 4: 运行时挂起与状态保存

上一课我们编写了简单的 while 循环执行队列。但假设某个节点是一个“人工审核 (Human Approval)”节点，用户需要离开页面，明天再来点击“同意”。我们如何在架构上实现这个工作流断点 (Workflow Breakpoint)？

控制反转：主动中断循环

要实现挂起，节点业务执行逻辑必须能够向执行引擎返回一个特殊的指令，告诉引擎：“我还没有完成，请停止整个队列的后续执行。”

// 节点的执行结果定义
type NodeExecutionResult = {
  status: 'SUCCESS' | 'FAILED' | 'SUSPENDED';
  outputData?: any;
};

// 执行引擎中的修改版 Loop
while (queue.length > 0) {
  const currentNode = queue[0]; // 注意：暂时不 shift 出队列
  
  const result = await executeNodeTask(currentNode);
  
  if (result.status === 'SUSPENDED') {
    // 触发断点挂起逻辑！
    saveWorkflowState(queue, completedNodes); // 持久化状态
    break; // 中断 while 循环，引擎进入休眠
  }
  
  if (result.status === 'SUCCESS') {
    queue.shift(); // 执行成功，移出队列
    completedNodes.add(currentNode.id);
    queue.push(...getOutgoers(currentNode));
  }
}
快照序列化 (State Snapshot)

当 break 触发时，系统会调用 saveWorkflowState。在这里我们极度庆幸在 Lesson 1 中设计了**双层状态架构**：我们不需要保存视图数据！我们只需序列化保存：

  • 当前剩余未执行的 queue (待执行列表)
  • 已经执行完成的 completedNodes 及其输出数据缓存
  • 当前整个执行图的唯一标识 ID

这三个数据组合起来，就是工作流断点的“现场快照”。

React/Redux/Zustand 中的挂起副作用

在你的 Zustand Store 中，当引擎触发 SUSPENDED 时，你可以派发一个 action 让 UI 层显示“流程已挂起：等待操作”。例如，在那个审核节点上方渲染一个“同意/拒绝”按钮。

🛠 知识固化测验

当引擎捕获到某节点返回了 `SUSPENDED` 状态并执行 break 时，此时执行队列 (Queue) 中位于它下游的节点会被执行吗？
