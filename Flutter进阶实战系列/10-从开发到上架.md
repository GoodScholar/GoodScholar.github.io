## 🔀 1. 多环境管理

### 方案：--dart-define 注入环境变量

```bash
# 开发环境
flutter run --dart-define=ENV=dev --dart-define=API_URL=https://dev-api.example.com

# 生产环境
flutter build apk --dart-define=ENV=prod --dart-define=API_URL=https://api.example.com
```

### 环境配置类

```dart
// lib/core/env.dart
class Env {
  static const String environment = String.fromEnvironment('ENV', defaultValue: 'dev');
  static const String apiUrl = String.fromEnvironment('API_URL',
      defaultValue: 'https://dev-api.example.com');
  static const bool isProd = environment == 'prod';
  static const bool isDev = environment == 'dev';
}
```

### Flutter Flavors（更完整的方案）

| 维度 | dart-define | Flavors |
|------|-----------|---------|
| 复杂度 | ⭐ 简单 | ⭐⭐⭐ 需改原生配置 |
| 支持修改 App 名 | ❌ | ✅ |
| 支持修改包名 | ❌ | ✅ |
| 支持修改图标 | ❌ | ✅ |
| 推荐场景 | API 地址/开关切换 | 正式项目多环境发布 |

```yaml
# 使用 flutter_flavorizr 快速配置
# pubspec.yaml
dev_dependencies:
  flutter_flavorizr: ^2.2.0

flavorizr:
  flavors:
    dev:
      app:
        name: "MyApp Dev"
      android:
        applicationId: "com.example.myapp.dev"
      ios:
        bundleId: "com.example.myapp.dev"
    prod:
      app:
        name: "MyApp"
      android:
        applicationId: "com.example.myapp"
      ios:
        bundleId: "com.example.myapp"
```

```bash
flutter run --flavor dev -t lib/main_dev.dart
flutter build apk --flavor prod -t lib/main_prod.dart
```

## 🤖 2. CI/CD 流水线

### GitHub Actions 完整配置

```yaml
# .github/workflows/release.yml
name: Build and Release

on:
  push:
    tags:
      - 'v*'  # 推送 tag 时触发构建

jobs:
  build-android:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.x'

      - run: flutter pub get
      - run: flutter analyze
      - run: flutter test

      # 构建 Android
      - run: flutter build appbundle
          --release
          --dart-define=ENV=prod
          --obfuscate
          --split-debug-info=build/debug-info

      # 上传构建产物
      - uses: actions/upload-artifact@v4
        with:
          name: android-release
          path: build/app/outputs/bundle/release/*.aab

  build-ios:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.x'

      - run: flutter pub get
      - run: flutter test

      # 安装 CocoaPods 依赖
      - run: cd ios && pod install

      # 构建 iOS（需要配置证书）
      - run: flutter build ipa
          --release
          --dart-define=ENV=prod
          --export-options-plist=ios/ExportOptions.plist

      - uses: actions/upload-artifact@v4
        with:
          name: ios-release
          path: build/ios/ipa/*.ipa
```

## 🚀 3. Fastlane 自动化

### 安装

```bash
# macOS
brew install fastlane

# 初始化
cd ios && fastlane init
cd android && fastlane init
```

### iOS Fastlane 配置

```ruby
# ios/fastlane/Fastfile
default_platform(:ios)

platform :ios do
  desc "Push to TestFlight"
  lane :beta do
    # 自动管理证书
    match(type: "appstore", readonly: true)

    # 构建
    build_app(
      workspace: "Runner.xcworkspace",
      scheme: "Runner",
      export_method: "app-store",
      output_directory: "./build",
    )

    # 上传到 TestFlight
    upload_to_testflight(
      skip_waiting_for_build_processing: true,
    )

    # 通知
    slack(message: "iOS Beta 已上传到 TestFlight ✅")
  end

  desc "Push to App Store"
  lane :release do
    match(type: "appstore", readonly: true)

    build_app(
      workspace: "Runner.xcworkspace",
      scheme: "Runner",
      export_method: "app-store",
    )

    upload_to_app_store(
      force: true,
      submit_for_review: true,
      automatic_release: true,
    )
  end
end
```

### Android Fastlane 配置

```ruby
# android/fastlane/Fastfile
default_platform(:android)

platform :android do
  desc "Deploy to Google Play Internal Testing"
  lane :beta do
    upload_to_play_store(
      track: 'internal',
      aab: '../build/app/outputs/bundle/release/app-release.aab',
      json_key: 'google-play-key.json',
    )
  end

  desc "Deploy to Google Play Production"
  lane :release do
    upload_to_play_store(
      track: 'production',
      aab: '../build/app/outputs/bundle/release/app-release.aab',
      json_key: 'google-play-key.json',
      rollout: '0.1', # 先 10% 灰度
    )
  end
end
```

### 一键发布

```bash
# iOS TestFlight
cd ios && fastlane beta

# iOS 正式上架
cd ios && fastlane release

# Android 内部测试
cd android && fastlane beta

# Android 正式上架
cd android && fastlane release
```

## 🍎 4. App Store 审核攻略

### 常见拒审原因 Top 10

| # | 拒审原因 | 频率 | 解法 |
|---|---------|------|------|
| 1 | 功能不够完整 | ⭐⭐⭐⭐⭐ | 确保核心功能全部可用 |
| 2 | 缺少隐私政策 | ⭐⭐⭐⭐⭐ | 必须有隐私政策页面 |
| 3 | 权限描述不清 | ⭐⭐⭐⭐ | Info.plist 写清楚每个权限的用途 |
| 4 | 截图不符 | ⭐⭐⭐ | 用真实截图，不要 PS |
| 5 | 登录问题 | ⭐⭐⭐ | 提供测试账号 + Apple Sign In |
| 6 | 内购实现有误 | ⭐⭐⭐ | 恢复购买按钮必须有 |
| 7 | 元数据违规 | ⭐⭐ | 不要在描述中提及其他平台 |
| 8 | 崩溃/Bug | ⭐⭐ | 提审前充分测试 |
| 9 | 第三方登录缺 Apple | ⭐⭐ | 有社交登录就必须加 Apple |
| 10 | 最低年龄不符 | ⭐ | 根据内容设置正确的年龄分级 |

### 审核 Checklist

**提审前必做：**
- [x] 隐私政策页面可访问
- [x] Info.plist 权限描述完整（中英文）
- [x] 如有第三方登录，必须提供 Apple Sign In
- [x] 如有 IAP，必须有「恢复购买」按钮
- [x] 审核备注中提供测试账号
- [x] 截图使用真机截取
- [x] App 描述不包含「Android」「Google」等字眼
- [x] 所有页面无明显 Bug 和崩溃

### Info.plist 权限描述模板

```xml
<!-- 相机 -->
<key>NSCameraUsageDescription</key>
<string>拍照上传头像需要访问您的相机</string>

<!-- 相册 -->
<key>NSPhotoLibraryUsageDescription</key>
<string>选择图片作为头像需要访问您的相册</string>

<!-- 通知 -->
<key>NSUserNotificationsUsageDescription</key>
<string>发送任务提醒和重要通知</string>

<!-- 位置 -->
<key>NSLocationWhenInUseUsageDescription</key>
<string>显示附近的服务网点需要获取您的位置</string>
```

## 🤖 5. Google Play 发布

### AAB vs APK

| 格式 | 优势 | Google Play 要求 |
|------|------|-----------------|
| AAB | 动态分发，按设备裁剪，体积更小 | ✅ 2024 年起强制要求 |
| APK | 通用格式 | ⚠️ 仍支持但不推荐 |

```bash
# 构建 AAB（推荐）
flutter build appbundle --release

# 构建 APK（按架构分包）
flutter build apk --split-per-abi --release
```

### 阶段性发布

```
内部测试 → 封闭测试 → 开放测试 → 正式发布
   ↓           ↓           ↓
  团队内       种子用户     公开 Beta     全量
```

## 📋 6. 版本管理

### 语义化版本

```
1.2.3+45
│ │ │  │
│ │ │  └── Build Number（Android versionCode / iOS CFBundleVersion）
│ │ └───── Patch：Bug 修复
│ └─────── Minor：新功能（向下兼容）
└───────── Major：破坏性变更
```

```yaml
# pubspec.yaml
version: 1.2.3+45
```

### 强制更新策略

```dart
// 检查版本，低于最低版本时强制更新
Future<void> checkUpdate() async {
  final remoteConfig = await fetchRemoteConfig();
  final minVersion = Version.parse(remoteConfig['min_version']);
  final currentVersion = Version.parse(packageInfo.version);

  if (currentVersion < minVersion) {
    showForceUpdateDialog(); // 不可关闭的全屏弹窗
  }
}
```
