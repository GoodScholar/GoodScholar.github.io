# 多平台文章写作 Skill 设计

## 目标

将现有 `wechat-article-writer` 从微信公众号专用写作 Skill 扩展为同时支持微信公众号和掘金的文章写作 Skill，同时保持现有公众号配置、系列状态和草稿箱发布能力可用。

## 平台路由

每次生成或改写文章前先确定目标平台：

- 当前请求或上下文明确为微信公众号时，直接进入微信公众号分支。
- 当前请求或上下文明确为掘金时，直接进入掘金分支。
- 未明确平台时，先询问用户选择“微信公众号”或“掘金”，得到答案后再继续。

修改已有文章时，如果用户已明确原稿的平台，则沿用该平台；无法判断时仍需询问。

## 结构设计

Skill 分为两层：

1. 通用写作流程：素材核验、事实与量化数据门控、写作参数、结构设计、真实案例、坑点、输出状态和修改模式。
2. 平台适配规则：根据目标平台选择排版、技术深度、图片、摘要、互动文案和发布方式。

微信公众号继续使用 `references/wechat-layout.md`。新增 `references/juejin-layout.md`，集中管理掘金 Markdown、代码块、标题层级、技术细节、链接与发布前检查规则，避免把两套规则混在正文流程中。

## 平台输出契约

### 微信公众号

- 面向移动端扫读，保持短段落和现有语义排版规则。
- 保留公众号摘要、转发文案、配图要求和单一 CTA。
- 用户明确要求发布时，继续使用现有草稿箱发布工具。

### 掘金

- 面向主动阅读的开发者，使用标准 Markdown 和清晰标题层级。
- 保留必要的完整代码、命令、日志、验证步骤和技术边界，不按公众号规则压缩成长图或短代码。
- 输出摘要、正文、标签建议和发布前检查；不强制朋友圈或社群转发文案。
- 图片按信息价值决定，不强制公众号封面裁切或橘猫正文图规则。
- 本次不新增掘金自动发布能力，只交付可直接粘贴到掘金编辑器的 Markdown。

## 兼容范围

- 保留 `.wechat-writer-config.json`、`.wechat-writer-series/`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET` 和 `publish_to_wechat.py`，不破坏既有公众号使用方式。
- 将 frontmatter 名称改为 `multi-platform-article-writer`，并更新触发描述、README、项目技能索引和相关路由说明，使“掘金文章”“掘金版本”“发布到掘金”等请求可以触发该 Skill。目录暂时保留 `WeChat-Insight-Skill`，避免无关的文件迁移。
- 与 `tech-article-expert` 的边界调整为：通用中文技术文章仍由 `tech-article-expert` 处理；明确面向公众号或掘金发布时，由本 Skill 处理平台适配。

## 验证标准

- 未指定平台的场景会先询问平台。
- 明确公众号的场景不会重复询问，并继续使用公众号排版与发布流程。
- 明确掘金的场景不会出现公众号摘要、朋友圈转发文案、微信编辑器限制或草稿箱发布步骤。
- Skill frontmatter 可通过现有 `quick_validate.py` 校验。
- 所有新增引用均存在，SKILL、README 和 `ARTICLE_SKILLS.md` 的平台描述一致。
